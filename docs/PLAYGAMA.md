# OpenTTD — Playgama publication and integration notes

This document describes the current **Playgama v12 ranking-ready** package for the OpenTTD 15.3 WebAssembly browser port.

## Package profile

- Engine: **Plain JS / WebAssembly** (Emscripten runtime)
- SDK: **Playgama Bridge JS Core stable v1 CDN** (`https://bridge.playgama.com/v1/stable/playgama-bridge.js`)
- Supported devices: **Desktop**
- Orientation: **Landscape**
- Languages: **English, Russian**
- In-app purchases: **No**
- Leaderboards: **Yes**, leaderboard id **`companyrating`**
- Multiplayer: **No** for this packaged browser edition
- Rewarded ads: **Disabled**
- Banner ads: **Disabled**
- Interstitial ads: **Enabled**, requested only at safe pauses

The release root contains `index.html` and is validated below Playgama's 300 MB unpacked package ceiling.

## SDK mapping and startup safety

The original browser shell uses a Yandex-style compatibility API. `playgama-yandex-compat.js` maps that interface onto Playgama Bridge so the OpenTTD runtime can share the same native game/runtime base with the Yandex Games edition:

- language -> Playgama platform locale;
- loading-ready -> Playgama game-ready message;
- gameplay start/stop -> Playgama lifecycle messages;
- fullscreen advertisement -> Playgama interstitial API;
- pause/resume -> Playgama pause-state events;
- platform mute -> Playgama audio-state events.

Playgama Bridge is **not a hard startup gate**. If the Bridge script is missing, blocked, or initialization fails, `YaGames.init()` returns an offline compatibility SDK so OpenTTD can still start. Platform-only features then degrade gracefully instead of leaving the game on an endless loading screen.

Native pause calls are made only after Emscripten reports `Module.calledRun === true`. AudioContext resume is attempted only after browser user activation, avoiding autoplay-policy failures during background/platform lifecycle events.

## Global ranking

The browser edition exposes the same native OpenTTD **Local ranking / Global ranking** UI on Playgama and Yandex Games.

Playgama uses `playgama/openttd-global-ranking.js` with the exact leaderboard identifier:

`companyrating`

The provider:

- preserves scores up to JavaScript's exact `Number.MAX_SAFE_INTEGER` range;
- submits with `bridge.leaderboards.setScore()`;
- reads entries with `bridge.leaderboards.getEntries()` only when `bridge.leaderboards.type === 'in_game'`;
- never opens authorization or a native leaderboard popup during background/startup polling;
- calls `bridge.player.authorize()` only after an explicit user action in the native ranking window;
- backs off failed entry requests for 30 seconds instead of flooding the console.

`playgama-bridge-config.json` declares `companyrating` as the main leaderboard.

### Optional Playgama SaaS leaderboard

For Playgama SaaS leaderboards, the production workflow supports a repository secret named:

`PLAYGAMA_SAAS_PUBLIC_TOKEN`

If that secret is configured, the Playgama package generated by `.github/workflows/build-v11-polished.yml` adds:

- `saas.publicToken` from the secret;
- `saas.leaderboards.platforms` for `playgama` and `qa_tool`.

The token is not committed to the repository and is not printed by the workflow. If the secret is absent, packaging remains valid and keeps the native/platform leaderboard configuration without inventing a token.

## Cloud saves

`openttd-playgama-cloud-saves.js` provides the active cloud-save implementation.

### Local persistence

OpenTTD continues to use Emscripten **IDBFS / IndexedDB** for the browser-local profile, configuration and `.sav` files. Local persistence remains available even when platform cloud storage cannot be used.

### Platform storage

When supported and available, the port uses Playgama platform storage.

The active cloud path does **not** use the previous small player-data layout. Instead:

- the newest `.sav` file is encoded and split into **64 KiB text chunks**;
- cloud data alternates between **slot A and slot B**;
- chunk data is written first and slot metadata is committed last;
- an interrupted upload therefore leaves the previous cloud generation recoverable;
- restored bytes are checked against the exact expected size and **CRC32**;
- a cloud save is restored only when it is newer than the newest local save;
- unchanged saves are not uploaded repeatedly;
- writes are serialized, debounced and throttled;
- legacy `openttdSaveV1` data is imported when no v2 slot exists;
- a **64 MiB per-save browser safety guard** prevents pathological memory usage. This is a client-side safety guard, not a claimed Playgama storage quota.

### Required QA save test

1. Start a game and create a manual OpenTTD save.
2. Wait for the local filesystem/cloud sync to complete.
3. Reload the QA build and confirm the save remains visible.
4. For a real cloud test, open the game on a different browser/device under the same platform user context and verify that the newer cloud save is restored.
5. Confirm that local saves still work when platform cloud storage is unavailable.

## Tutorial and button guide

Both platform editions use the same rebuilt native OpenTTD runtime. The package therefore includes the browser-edition tutorial and button guide compiled into OpenTTD itself:

- a dedicated training game;
- 20 guided steps covering the core transport/economy mechanics;
- yellow highlighting of the required toolbar control;
- directional arrow hints;
- an illustrated main-menu guide;
- an illustrated in-game toolbar guide;
- Russian and English tutorial text.

The tutorial is compiled and validated by `.github/workflows/tutorial-compile-probe.yml`.

## Bundled AI and optional content

The package includes SimpleAI and required AI libraries. It also ships seven optional local add-on/base-graphics packages:

- Iron Horse 4
- FIRS Industries 5
- Road Hog
- GIST — German Industries Set
- Early Vehicle Set
- OpenGFX2 Settings
- OpenGFX2 Classic

NewGRFs remain **disabled by default** and are enabled by the player for a new game. FIRS and GIST are alternatives and should not be enabled together.

The distribution uses neutral `.bin` asset filenames for gzip-compressed add-on payloads to avoid CDN/content-encoding ambiguity. The manifest still verifies packaged and installed hashes.

## Playgama console text

### Game description

OpenTTD is an open-source transport management simulation game. Build and manage railways, roads, airports and shipping routes, transport passengers and cargo, develop an efficient transport company, and expand your network across a living world. This browser edition includes computer-controlled competitors, an interactive tutorial, rankings, and optional additional vehicle, industry and graphics content.

### How to play

Use the mouse to navigate menus, select tools and build your transport network. Create railway tracks, roads, stations, airports and docks, then purchase vehicles and assign routes to transport passengers and cargo. Earn money from successful deliveries, improve your infrastructure and expand into new cities and industries. You can zoom and move around the map with the mouse and use keyboard shortcuts for faster control. New players can start the built-in interactive tutorial, which highlights the required controls and explains the core mechanics step by step. The goal is to build a profitable and efficient transport company and continue developing it over time.

## Certification notes

- Authorization: the ranking provider never auto-opens authorization; sign-in is requested only after explicit player action when the platform supports it.
- Leaderboard id: **`companyrating`**, without underscores or separators.
- Rewarded Ads: there is no rewarded-ad mechanic and the Bridge config disables rewarded ads.
- Interstitial Ads: requested only at safe pauses by the integration layer.
- Sensitive content: standard OpenTTD gameplay does not contain realistic violence, blood, gambling, sexual content or drug use.
- Scale: the SDL/OpenTTD canvas uses the complete browser viewport; no forced 16:9 letterbox is applied.
- Startup: Bridge/storage/platform feature failures must not prevent the core OpenTTD runtime from starting.
- Add-ons: verify that the NewGRF menu lists the bundled optional NewGRFs; OpenGFX2 Classic is selected through the base-graphics setting rather than the NewGRF list.

## CI / release architecture

`.github/workflows/build-v11-polished.yml` produces **two artifacts from one rebuilt native OpenTTD base**:

1. `openttd-playgama-v12-ranking`
2. `openttd-yandexgames-v12-ranking`

The Playgama package is built and validated first. The Yandex Games package is then copied from that exact base and only the platform SDK layer is swapped. Native OpenTTD runtime changes, tutorial UI, NewGRFs, ranking core and game logic therefore stay synchronized between the two editions.

`.github/workflows/dual-platform-ranking-probe.yml` separately exercises both leaderboard providers and the Playgama offline-startup fallback.
